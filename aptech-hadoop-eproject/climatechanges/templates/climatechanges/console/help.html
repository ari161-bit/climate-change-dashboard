User guide

What each section of the console does

Overview: headline climate indicators (global temperature change, average temperature, rainfall, humidity, CO₂, anomalies, processing statistics), a trend + forecast chart and the latest alerts. Use the filter bar to narrow by dates, region, country and variable.
Climate Analytics: interactive charts for temperature trends, historical vs predicted values, a world anomaly map, rainfall by station, humidity by region, CO₂ and regional comparisons. Hover for exact values; scroll to zoom the map.
Data Management: upload CSV/JSON tables or GeoTIFF imagery. Tables are profiled (missing values, duplicates, column types) with a preview and can be cleaned or imported as readings. GeoTIFF files are encrypted and catalogued as source imagery; both tables and imagery can be stored in HDFS.
Data Processing: runs MapReduce jobs (locally or on Hadoop), ML training, anomaly scans and alert evaluation; shows HDFS and MongoDB status, CPU/memory/disk use, request timings, logs and backups.
Predictions: temperature models compared on years they never saw, the forecast with its uncertainty band, and the rainfall model compared with a seasonal baseline.
Anomaly Detection: unusual temperatures by country (z-score), unusual station readings (Isolation Forest) and correlations, including temperature vs climate disasters.
Alerts: every alert with severity and read/unread status. The bell in the top bar shows how many are unread. Administrators set the thresholds.
Reports: six report types (summary, temperature, rainfall, anomalies, predictions, regional) as PDF or CSV.
Support: send a question, report a problem or give feedback, and follow its status until it is resolved.
Settings: profile and password. Administrators also manage users and roles, and schedule maintenance notices.

Roles. Climate Analyst: everything above except user management, alert-threshold editing, maintenance notices, backups and log viewing. Administrator: everything.

Tutorials

Step by step

1 · Upload and clean a station dataset

  1. Open Data Management.
  2. Choose sample_data/station_readings_sample.csv, type Weather station records, then Upload & validate.
  3. Check the profile: 4 missing values and 2 duplicate rows are reported.
  4. Click Clean data: duplicates are removed and numeric gaps filled with the column median.
  5. Click Import as station readings: the readings appear in dashboards and are checked against alert rules (the 46.5 °C reading raises an alert).
  6. Click Store in HDFS: the cleaned file is written to /climate/clean/station/year=…/month=…/.

2 · Run a Hadoop MapReduce job

  1. Start Hadoop with hadoop\start_hdfs.cmd (keep its windows open).
  2. Open Data Processing; HDFS should show Online.
  3. Choose Climate disasters per year on Hadoop and click Run job (about 15 s).
  4. The job page shows the engine hadoop-streaming, the output chart and the HDFS output path.

3 · Get a forecast report

  1. Open Predictions and pick a country or region.
  2. Read the model comparison (lower RMSE = better).
  3. Open Reports, choose Prediction results, then PDF.

4 · Set a heat alert (administrators)

  1. Open Alerts → Add a new rule.
  2. Variable Temperature, above, threshold 38, severity Critical.
  3. Click Evaluate rules now; new readings are checked automatically.

5 · Send real-time sensor data

  1. POST JSON to /climatechanges/api/ingest/ with header X-API-Token.
  2. Example body: {"station":"Dakar","timestamp":"2026-11-01T12:00:00Z","temperature":31.2,"rainfall":0,"humidity":61}
  3. The reading is stored (SQL + MongoDB), shown on dashboards and checked against alert rules immediately.

Frequently asked questions

What does the “sample data” badge mean?

The project ships with real temperature, disaster and carbon datasets, but not real station rainfall/humidity history. Those station readings are generated for demonstration and are always labelled sample data. Upload real station data or pull live data to replace them.

Which numbers are real?

Temperature change (FAO, 1961-2023), climate disasters (EM-DAT, 1980-2024), forest carbon (FAO), CO₂ (NOAA Mauna Loa) and live weather (Open-Meteo). Each chart shows a badge.

Why does HDFS show “offline”?

Hadoop isn't running. Start it with hadoop\start_hdfs.cmd. Until then the app stores files in a local staging folder with the same layout and runs jobs on its built-in MapReduce engine, and it tells you so.

How accurate are the predictions?

See the Predictions page. Every model is tested on data it did not train on (the last 10 years for temperature). The MAE, RMSE and R² shown are measured, not estimated.

Which file formats can I upload?

CSV and JSON (a list of records, or an object containing one), up to 20 MB. Station data is detected automatically from column names such as station, date, temperature, rainfall/precipitation, humidity.

Are my uploads safe?

Uploaded and cleaned files are encrypted on disk (AES with an integrity check) and can only be downloaded by signed-in users. Backups are encrypted too.

How do I mark all alerts as read?

Alerts → Mark all read. Read status is per user.

I forgot my password.

Ask an administrator to reset it from the Django admin (Users), then change it yourself in Settings.

Where can I see the data in MongoDB?

Open MongoDB Compass, connect to mongodb://127.0.0.1:27017 and open the earthscape database.

How do I open the data in Tableau?

Reports → Tableau / BI extract downloads ready-to-use CSV tables; see docs/TABLEAU_GUIDE.md.

How EarthScape follows common climate-data conventions

AspectStandard / conventionIn EarthScape
UnitsSI / CF conventionstemperature °C (degC), rainfall mm, humidity %, CO₂ ppm; units in every API response and report
TimeISO 8601, UTCall timestamps stored in UTC, exported as ISO 8601 (e.g. 2026-11-01T12:00:00+00:00)
LocationWGS 84 (EPSG:4326), GeoJSONlatitude/longitude in decimal degrees; MongoDB stores a GeoJSON Point
CountriesISO 3166-1 alpha-2/alpha-3datasets keep ISO2/ISO3 codes; maps use ISO-3
Temperature anomalyWMO baseline practicechange vs 1951-1980 climatology (FAO definition)
ProvenanceISO 19115 lineage / FAIR principlesevery reading keeps its source; every chart shows real/sample status and the data source
Big-data layoutHive-style partitioning/climate/<zone>/<kind>/year=YYYY/month=MM/ in HDFS
